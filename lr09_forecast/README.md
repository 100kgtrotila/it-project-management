## 2. Як рахувалася симуляція


| Поле | Значення |
| --- | --- |
| Інструмент | Python, стандартна бібліотека; код нижче |
| Прогонів | 10 000 на кожний набір |
| Seed | 20261025, генератор заново для кожного набору |
| Що тягнеться випадково | Одне значення `points_done` із вибраної історії, рівноймовірно з поверненням |
| Перцентилі | Найближчий ранг: відсортований елемент `ceil(q × N) − 1`; результат уже цілий спринт |
| Дата для всього REL-1 | Кінець спринта 1 + (P − 1) × 14 днів |
| Дата для залишку | Кінець останнього закритого спринта + P × 14 днів |

Код можна запустити в Python без сторонніх бібліотек. Список `reference` містить колонку `points_done` офіційного `lr09_reference_velocity.csv`. Для проєкту викликано simulate([0, 8], 52) і simulate([0, 8], 44). Для кожного набору генератор починається із seed 20261025.

```python
import math
import random

def simulate(history, remaining, simulations=10000, seed=20261025):
    if not history or any(v < 0 for v in history) or remaining < 0 or simulations < 1000:
        raise ValueError("Invalid inputs")
    if remaining > 0 and max(history) == 0:
        raise ValueError("No finite forecast: all velocity values are zero")
    rng = random.Random(seed)
    results = []
    for _ in range(simulations):
        left, sprints = remaining, 0
        while left > 0:
            left -= rng.choice(history)
            sprints += 1
        results.append(sprints)
    results.sort()
    return tuple(results[math.ceil(q * simulations) - 1] for q in (0.50, 0.85))

reference = [21, 17, 26, 14, 23, 6, 28, 12, 22, 25, 18, 9]
for label, history in (
    ("all12", reference),
    ("first2", reference[:2]),
    ("sprints5and6", reference[4:6]),
):
    print(label, simulate(history, 220))
```

Цикл припиняється при залишку 0 або менше: рівно досягнута ціль не додає зайвий спринт. Нуль серед інших значень є законною вибіркою й подовжує прогін. Для нульового обсягу результат 0/0 спринтів; для позитивного обсягу й лише нульової velocity повертається помилка відсутності скінченного прогнозу.


Фактичні періоди мають різну тривалість: 13 та 5 днів між датами. Власний прогноз нижче є навчальним сценарієм: майбутній крок триває 14 днів, завершення за крок незалежно набуває 0 або 8 SP з однаковою ймовірністю. Це припущення про майбутнє, а не доведена швидкість команди. Значення 8 не масштабували з п’яти днів до чотирнадцяти. P85 означає 85% лише всередині цієї моделі; неоднакова тривалість і два спостереження не дозволяють трактувати її як перевірену ймовірність реального строку.

## 3. Дві дати першого релізу

| Сценарій з кроком 14 днів | Points | P50, кроків | P85, кроків | P50, дата | P85, дата |
| --- | ---: | ---: | ---: | --- | --- |
| Весь перший реліз | 52 | 13 | 18 | 2027-04-10 | 2027-06-19 |
| Залишок після двох спринтів | 44 | 11 | 16 | 2027-04-02 | 2027-06-11 |

REL-1 містить 52 SP. Прийнята лише S-01: 52 − 8 = 44 SP залишку. Для всього релізу база — кінець першого спринта 24 жовтня плюс (P − 1) × 14; для залишку — 30 жовтня плюс P × 14. Наприклад, P85 залишку: 2026-10-30 + 16 × 14 днів = 2027-06-11. Друга дата є робочим орієнтиром сценарію, бо враховує вже прийнятий обсяг; вона не є зобов’язанням щодо строку.

## 4. Прогноз проти критичного шляху з ЛР7

| Джерело | Дата REL-1 |
| --- | --- |
| Roadmap ЛР7 після ресурсного вирівнювання | 2027-06-25 |
| Сценарний P85 залишку | 2027-06-11 |
| 20 календарних тижнів V12 від 2026-10-19 | 2027-03-08 |

Сценарний P85 на 14 календарних днів раніший за roadmap, але на 95 днів пізніший за строк V12. У ЛР7 100-й робочий день включно зі стартом — 5 березня; додавання рівно 20 календарних тижнів дає 8 березня. Різниця зумовлена правилами відліку. CPM становить 164 робочі дні, ресурсний календар — 180; Monte Carlo оперує SP та випадковими завершеннями, тому дати не мають збігатися.

Зберігаємо roadmap як ресурсний план: слабкий сценарний прогноз не є підставою його прискорювати. До зобов’язання щодо строку потрібні новий повний двотижневий вимір та перегляд обсягу при фіксованій даті. Варіант скорочення should-історій потрібно перевірити на покриття SC-01–SC-03; поточний склад REL-1 не змінений.

## 6. Що я кажу замовнику

За навчальним сценарієм із завершеннями 0 або 8 SP за кожні 14 днів залишок має P85 11 червня 2027 року; 85% стосується лише цієї моделі. Через два спостереження різної тривалості дату використовуємо як орієнтир для обговорення обсягу. Якщо потрібна раніша дата, спочатку перевіряємо скорочення релізу зі збереженням критеріїв успіху, потім перераховуємо план і прогноз.

Перерахунок — після наступного повного 14-денного періоду, зміни складу REL-1 або переоцінки історії з великим розкидом. Зміна безпеки ЛР11 залишається deferred, тому в розрахунку 52 SP, без додавання попередніх 13 SP.

Рішення CH-03 не збільшило обсяг: 52 SP загалом і 44 SP залишку. Причина раннього закриття — приймання всього взятого обсягу; втрачені 8 днів спостереження означають, що 0/8 не можна порівнювати як рівні двотижневі виміри. Першу перевірку цієї моделі робимо на наступному повному 14-денному інтервалі. Приймання F-001 не додає продуктових SP: це процесна картка, а S-09 залишається поза REL-1.
