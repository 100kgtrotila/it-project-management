## 3. Definition of Done

У [dod.md](dod.md) сім перевірюваних умов: критерії, сценарії ролей, відсутність блокувальних дефектів, повторна самоперевірка, приймання й узгоджені записи. У ЛР2 лишається початкова вимога end-to-end перевірки та демо; тепер уточнено, як її застосовувати до навчального проєкту без обов’язкового коду. Навчальний розбір не видаємо за випробування працюючої системи або відповідь реального замовника. Другого рецензента замінено самоперевіркою наступного дня.

## 4. Технічний борг

| Поле | Значення |
| --- | ---: |
| Записів | 3 |
| Разом оцінок повернення | 5 годин |
| Стеля V12 | 2200 годин |
| Частка стелі | 5 / 2200 × 100 = 0,23% |
| pay_now / pay_later / accept | 0 / 2 / 1 |
| Перенесено до спринта 3 | 4 години |

Це оцінки витрат на процес і документацію. D-01 — пропущені старти п’яти F-карток: без них вибірка cycle time неповна. D-02 — свідоме ручне ведення однакових історій у CSV й Issues: воно дозволило почати роботу без автоматизації, але кожне уточнення потребує подвійної перевірки. D-03 — порушений порядок сліпого оцінювання ЛР8.

D-03 приймаємо з розкритим обмеженням: повторення сесії зі знанням конверта не відновить початкову незалежність. Одна година в реєстрі — оцінка окремої незалежної повторної сесії, а не запланована робота. Для D-01 дві години означають перевірку доступної історії, а не гарантію відновлення відсутніх дат.

Наслідок для замовника: неповні дати послаблюють аналіз потоку, а дублікати описів можуть дати різні очікування щодо однієї задачі. Чотири години звірки зменшують ці ризики; вони не є часом реалізації невиконаних S-історій. 27 жовтня перевірено всі 18 S-Issues, тоді всі були відкриті. Повторна звірка 30 жовтня підтвердила ключі та всі критерії CSV; S-01 закрита, решта не прийняті. Дублювання описів зберігається, тому D-02 не погашено: перевірку доведеться повторювати після змін. Для D-01 30 жовтня перевірено історію п’яти Issues: відновлено перший Review 11 жовтня, але фактичний старт не підтверджений; його наступна дія й повторна звірка D-02 перенесені у спринт 3 без списання оцінених годин.

Це оцінка додаткової роботи, а не заміна оцінки всієї S-01 у 8 SP. Інтеграція входу припускає наявний тестовий провайдер академії. Гостьові акаунти для баз тут не оцінені: їхню можливість ще має визначити служба. Години оцінено окремо: для входу 8 BA + 32 Dev + 16 QA + 8 DevOps; журналу 8 BA + 40 Dev + 16 QA; сторінки 8 BA + 16 Dev + 8 QA. SP у години не конвертували.

За умовною бюджетною ставкою статуту 500 грн/год додаткова праця коштувала б 80 000 грн. Це 72,73% надбавки 110 000 грн; лишалося б 30 000 грн до інших витрат. 1640 + 160 = 1800 годин нижче стелі 2200, але один Dev уже завантажений на 720 із 800 годин: додаткові 88 дадуть 808, перевищення на 8. Бюджетна надбавка сама по собі не збільшує доступність Dev.

Конфлікт: лист вимагає вхід через акаунт академії, а SC-02, S-15 і S-18 — зовнішнє оцінювання без нього. Рішення залежить від служби інформаційної безпеки й керівника практики. Пропозиція для погодження: академічний вхід для внутрішніх ролей та окремо дозволений зовнішній доступ за відкличним запрошенням. Виняток ще не дозволений. Альтернатива — гостьові акаунти академії, але вона змінить SC-02 і вимагатиме переоцінки зовнішнього сценарію.

Включення зміни до REL-1 відкладаємо до цього рішення та узгодження строку. Без усіх трьох вимог або явно погодженого винятку академія не прийме систему; наслідок несуть керівник практики як замовник і спонсор. Ручний облік залишиться потрібним для всіх близько 100 студентів із контексту теми; за припущенням статуту це 25 годин звірки одного пакета. Це оцінка навантаження, не виміряні додаткові витрати.

Якби взяли зміну без скорочення, реліз зріс би з 52 до 65 SP. Для обміну в межах 52 SP потрібне вилучення 13 SP. Наприклад, S-17 (5) + S-03 (5) + S-11 (3) дають 13, але прибирають огляд нестач, подання заявки й підтримку довідника; без довідника страждає і S-05. Такий обмін не прийнято. Крім того, чинний ресурсний календар уже перевищує V12 на 80 робочих днів: червнева дата ЛР7 є непогодженою альтернативою, а не дозволом спонсора перенести практику.

Беклог, склад REL-1, оцінки й календар за рішенням deferred не змінені; нових ключів історій не створено. Оцінки відкладеної зміни збережені в розділі 5; до чинних оцінок REL-1 вони не додані. Ризики події — R-05 і R-06. Сценарний прогноз ЛР9 розраховано після огляду 30 жовтня: весь реліз 52 SP, залишок 44 SP; припущення для різної тривалості описані в ЛР9. Після рішення щодо доступу потрібно знову розглянути зміну й додати новий рядок журналу, а не переписати CH-01.

Представник служби інформаційної безпеки доданий до карти як ST-06; вона охоплює шість ролей. SC-02, обсяг 52 SP і рішення deferred зберігаються.

Подію безпеки не оголошено виконаною.
