## Рішення по зауваженнях

Отриманих зауважень немає, тому рішень про прийняття або відхилення ще не ухвалював. Після появи рецензії для кожного пункту запишу рішення, конкретний файл і строк виправлення до дедлайну. 30 жовтня повторно перевірю посилання; якщо рецензія не з’явиться, зафіксую відсутність на дедлайн і повідомлю викладача.

## Що я забрав із чужого портфеля

Власна [рецензія на neRoma32](review.md), розділ 4: запис Given/When/Then робить передумови перевірки явними. Для моєї S-11 підготував три сценарії без зміни її обсягу й оцінки:

| Given | When | Then |
| --- | --- | --- |
| Користувач має роль адміністратора, ID бази ще немає в переліку | Додає базу з цим ID | У переліку є один новий запис |
| База є в переліку, але ще не опублікована | Студент відкриває перелік; після публікації повторює перегляд | До публікації бази не видно, після публікації видно |
| У переліку вже є база з указаним ID | Адміністратор повторює додавання того самого ID | Другий запис не створюється |

Це підготовка перевірки. S-11 лишається Ready поза обсягом спринта 2, без дати завершення і без зарахованих SP.

## Що я перевірю сам перед захистом

- Власний прогноз має спиратися на дві фактичні velocity, а не на 10 SP ємності V12; дати та суми повинні збігтися з журналом спринтів.
- У змінах після листа безпеки окремо названо конфлікт акаунта академії зі SC-02. Додавання стейкхолдера не означає, що він уже погодив виняток або що вимоги листа виконані.
